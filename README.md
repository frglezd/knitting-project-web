# Knitting Catalog

A Spring Boot REST API + static frontend for managing a catalog of knitting supplies (yarn, needles, accessories, etc.), backed by PostgreSQL.

## Prerequisites

- Java 21
- PostgreSQL (13+ recommended)
- No Node.js/build tools needed — the frontend is plain HTML/CSS/JS served by Spring Boot itself.
- The Maven wrapper (`mvnw` / `mvnw.cmd`) is included, so a separate Maven install isn't required.

## Database setup

1. Create the database matching [application.properties](src/main/resources/application.properties) (defaults: user `postgres`, password `password`, db `knitting_catalog`):

   ```sh
   createdb knitting_catalog
   ```

   Connection settings are read from environment variables, falling back to the local defaults above if unset:

   | Variable      | Default                                          |
   |---------------|---------------------------------------------------|
   | `DB_URL`      | `jdbc:postgresql://localhost:5432/knitting_catalog` |
   | `DB_USERNAME` | `postgres`                                         |
   | `DB_PASSWORD` | `password`                                         |

   Set these instead of editing `application.properties` if your Postgres instance uses different credentials.

2. Create the schema. You have two options:

   - **Automatic**: leave `spring.jpa.hibernate.ddl-auto=update` as-is (already the default in this repo) and Hibernate will create the `catalogo` table for you the first time the app starts.
   - **Manual / from scratch**: run the provided schema file instead:

     ```sh
     psql -U postgres -d knitting_catalog -f db/schema.sql
     ```

     This creates the `catalogo` table:

     ```sql
     CREATE TABLE catalogo (
         id             INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
         nombre         VARCHAR(150)   NOT NULL,
         categoria      VARCHAR(100)   NOT NULL,
         fabricante     VARCHAR(150)   NOT NULL,
         precio         NUMERIC(10,2)  NOT NULL,
         unidad_precio  VARCHAR(20)    NOT NULL,
         imagen         TEXT,
         descripcion    TEXT
     );
     ```

     Note: `id` auto-increments (Postgres identity column). It's still possible to insert an explicit `id` (e.g. for the sample data below), but omitting it — as the frontend and API do — lets the database assign the next value.

3. (Optional) Load sample data from [db/sample_items.csv](db/sample_items.csv):

   ```sh
   psql -U postgres -d knitting_catalog -c "\copy catalogo(id,nombre,categoria,fabricante,precio,unidad_precio,imagen,descripcion) FROM 'db/sample_items.csv' WITH (FORMAT csv, HEADER true)"
   ```

   Since the sample data inserts explicit `id` values, resync the identity sequence afterward so new items (created via the API/frontend) don't collide with them:

   ```sh
   psql -U postgres -d knitting_catalog -c "SELECT setval(pg_get_serial_sequence('catalogo', 'id'), (SELECT MAX(id) FROM catalogo))"
   ```

## Running the app

```sh
./mvnw.cmd spring-boot:run   # Windows
./mvnw spring-boot:run       # macOS/Linux
```

The app starts on `http://localhost:8080`:

- Frontend: `http://localhost:8080/`
- API: `http://localhost:8080/api/v1/item`

## API endpoints

| Method | Path                          | Description                          |
|--------|-------------------------------|---------------------------------------|
| GET    | `/api/v1/item`                | List all items (or filter with `?nombre=`) |
| GET    | `/api/v1/item/{itemId}`       | Get one item by ID                    |
| POST   | `/api/v1/item`                | Create an item                        |
| DELETE | `/api/v1/item/{itemName}`     | Delete an item by name                |
| DELETE | `/api/v1/item/id/{itemId}`    | Delete an item by ID                  |
